# Acceso privado de Arbigen

La fase 18 sustituye `X-Demo-Workspace-ID` por cuentas y sesiones persistidas en PostgreSQL. La migración `0004_auth_sessions` añade `users.password_hash` y `auth_sessions`; no borra ni reasigna usuarios o investigaciones de la demo anterior. Cada ruta de investigaciones y Dashboard obtiene el `user_id` exclusivamente de una sesión válida y filtra las consultas por ese propietario.

El registro requiere `AUTH_REGISTRATION_CODE` (mínimo 24 caracteres) en el backend. No existe un código predeterminado: sin la variable, `/api/v1/auth/register` responde 503. El código actual se guarda en `backend/.env` para desarrollo y debe cargarse como variable **Secret** de Production únicamente en `arbigen-api`; nunca en Angular, Git o Preview. Es un código compartido y reutilizable: después de invitar a alguien, puede rotarse en Vercel para impedir nuevos registros con el anterior, sin cerrar las sesiones ya creadas.

Las contraseñas se derivan con Argon2 mediante `pwdlib`. Al iniciar sesión, el backend crea un token aleatorio, guarda únicamente su SHA-256 y lo envía como cookie `__Host-arbigen_session` con `HttpOnly`, `Secure`, `SameSite=Strict` y `Path=/` en Production. La sesión caduca a los siete días o se revoca al cerrar sesión. `/api/v1/auth/me` devuelve usuario y token CSRF al mismo origen; cada escritura requiere `X-CSRF-Token` y un `Origin` incluido en `CORS_ORIGINS`. Las respuestas de `/api/v1/` llevan `Cache-Control: private, no-store`. El frontend mantiene usuario y CSRF solo en memoria y recarga la sesión desde la cookie; no guarda credenciales en `localStorage`.

Para Production, establecer `ENVIRONMENT=production`, `CORS_ORIGINS=["https://arbigen-web.vercel.app"]` y el código de invitación en `arbigen-api`, aplicar `0004` fuera del build y volver a desplegar ambos proyectos. La reescritura `/api` de `arbigen-web` permite usar cookies del mismo origen. No copiar credenciales de la base al frontend. El registro y las pruebas de sesión pueden verificarse con cuentas de prueba; no iniciar Apify para probar autenticación.

Esta fase no verifica la propiedad del correo, no ofrece recuperación de contraseña ni MFA y todavía no incorpora una limitación persistente de intentos de inicio de sesión. El código de invitación restringe el registro, pero no equivale a un sistema de invitaciones individuales. Antes de almacenar información personal o abrir el registro a terceros, completar esos controles y revisar las políticas de acceso. Las investigaciones locales antiguas requieren una migración explícita de propiedad a la nueva cuenta; conocer un UUID demo no permite reclamarlas.
